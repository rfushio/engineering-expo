# 確定仕様・構成

2026-11-06時点の初版。企画書 `idea.md` は変更していない。

## ルール

- 一台のMacに盤面を表示し、同じWi-FiにあるiPhone 2台から操作する。参加順にP1（青）、P2（オレンジ）。
- スマホは横持ち。移動は出現位置を固定するフローティングスティック、磁場は独立した長押しボタン。スティックの半径の12%を遊びとし、それ以外は倒す量に比例して移動する。左右配置を交換できる。
- カーソルは盤面全体を移動し、端で止まる。盤面は周期境界ではない。
- 磁場は徐々に磁化を反転させる。双方が同じ場所にかける逆向きの外場は加算して相殺する。自然な緩和は止まらず、双方のゲージを消費する。
- ゲージは満タンで3秒分。ボタンを離すと4秒で空から満タンへ戻る。途中回復分も使用できる。領土面積による回復率の差はない。
- 開始前の双方の準備完了から3秒カウントダウン。75秒の操作後、5秒の自然緩和を経て面積で決着する。厳密な同面積は引き分け。
- 最後の5秒は移動も磁場も停止する。領土ゼロで即敗北にはならない。
- 固定盤面は橋の切断・島の救援・複数の前線。各盤面の磁化は180度回転と色交換に対して対称で、初期面積は50対50。
- 練習は時間制限なし。最初に接続している一人が操作し、相手は操作しない。

## 数値モデル

格子は192×108。格子間隔を1とする無次元Allen–Cahn型方程式を、5点差分と陽的Euler法で計算する。

```text
dm/dt = relaxation * [8 * Laplacian(m) + 4 * (m - m^3)] + h1 + h2
```

- 標準の時間刻みは1/240秒。60Hzのゲーム更新ごとに4小ステップを実行する。
- 壁の外側の隣接値には境界格子の値を使う（法線方向勾配ゼロ）。
- 外場は半径R以内で `sign * strength * (1 + cos(pi * r/R)) / 2`、外側はゼロ。P1は正、P2は負。
- 初期値：半径8格子、強度14、自然緩和倍率1、移動速度60格子/秒、使用時間3秒、回復時間4秒。
- 最後のわずかな残量は、その更新の磁場強度を残量に応じて減らして使い切る。
- 調整範囲：半径3–14、強度2–20、自然緩和倍率0.25–2、速度20–100、使用時間1–10秒、回復時間1–12秒。
- 磁化はFloat64で保持する。計算中の値を±1に切り詰めない。描画用の値だけを±1へ制限して8bitに変換する。
- 面積は元のFloat64値の正負から数える。ゼロは0.5ずつ配分する。表示比率は小数一桁に丸めるが、勝敗は丸め前の面積で決める。
- 孤立・接続を判別して消滅や保護を追加する処理はない。連結成分の計算は検証用テストだけで使う。

## 通信・状態

Node.jsサーバーが計算と勝敗の唯一の管理元。ブラウザ同士の同期計算は行わない。

| 経路 | 用途 |
|---|---|
| `/host` | PCの表示・設定画面 |
| `/controller?room=…` | スマホ参加・操作画面 |
| `/api/host-info` | localhost限定。参加先とPC管理用のトークンを取得 |
| `/api/health` | 起動確認 |
| `/ws` | WebSocket接続 |

最初に役割と参加情報を送信する。スマホの通常入力は30Hzで、移動ベクトルと磁場ボタンの真偽値だけを送る。指を離す・操作中断などの解除通知は即時送信する。サーバーは移動ベクトルの長さを1以下に制限する。

状態はJSONで約30Hz配信。PCにだけ192×108の8bit磁化フレームを追加配信する。スマホに盤面は送らない。送信が詰まった場合は古い描画フレームを送ることを避ける。表示更新はブラウザの描画周期に合わせる。

各スマホには再接続トークンを割り当て、同じブラウザで同じ枠に戻せる。新規の3台目は拒否。同じトークンの別タブが接続した場合、元の接続を止めて試合を一時停止する。参加コードは起動ごとに変わる。PC管理はlocalhostからのトークン付き接続に限定する。

```text
待機 → 準備完了 → 3秒カウントダウン → 操作75秒 → 緩和5秒 → 結果
                                       ↓            ↓
                                     一時停止 ← 接続断・画面ロック
                                       ↓
                              再接続・双方の準備完了
                                       ↓
                                3秒後に元の段階へ戻る
```

- 350ms入力が来ない場合は移動・磁場を解除する。
- 通信の応答は500ms間隔。1.5秒応答がない場合は切断扱い。
- スマホが非表示・縦向きになると参加者を一時的に不在とする。PC画面の非表示、最後のPC表示の切断も停止する。
- 一時停止時は盤面・ゲージ・試合時計を凍結し、全員の入力と準備完了状態を解除する。
- PCの処理間隔が500msを超えた場合や、12更新以上の遅れが残る場合は、時間を飛ばさず一時停止する。
- 待機・結果画面で設定可能。練習だけは停止中にも設定・盤面リセットができる。設定はサーバー再起動で初期化する。

## ソースの分担

- `src/shared/`：定数、設定の範囲、通信と状態の型。
- `src/server/`：数値計算、対戦状態、HTTP/WebSocketサーバー。
- `src/client/`：PC描画、スマホ入力、接続復帰、画面スタイル。
- `tests/`：数値モデル・ルール・実サーバー通信とブラウザ操作の検証。

初版では、有線・オンライン遠隔対戦・CPU・タッチパッド・盤面直接タッチ・障害物・戦績保存・効果音は実装しない。


## 立体版（表示の別バージョン）

`/host?view=3d` で開始する。既存の `/host` は平面版を標準とし、どちらからでも表示を切り替えられる。別の対戦セッションを作るものではなく、同じ試合への二種類の表示である。

描画は `src/client/relief.ts` に分離し、立体版でだけThree.jsを遅延ロードする。サーバーの数値計算・通信・スコアリングは変更していない。スマホにも3Dライブラリを読み込まない。

- サーバーから届く既存の8bit描画用磁化を `m_display = byte / 127.5 - 1` として読み、高さを `起伏倍率 × m_display` にする。元の磁化が±1を超える部分は、描画用フレームの仕様により高さも飽和する。
- 起伏倍率の初期値8、範囲3–14。カメラは正投影で、盤面の水平軸を保ったまま35–75度の範囲で見下ろす。初期角度52度。
- 192×108の頂点を持つ面を更新し、法線を再計算する。外周の側面・台座と陰影を付け、磁区の高低を見やすくする。
- P1の正の外場にはS極が下向きの棒磁石、P2の負の外場にはN極が下向きの棒磁石を対応させる。N半分を赤、S半分を白で表示し、P番号と下向きの極を別のラベルでも示す。
- 磁石は盤面の上に浮かび、作用中に下がる。地形に沿う範囲リング、中心の点線、作用時の光の線を表示する。極の描画は局所外場の操作を説明するもので、棒磁石の三次元磁場を別途解いてはいない。
- 表示切替と起伏・視点の変更はクライアント内で完結し、準備状態・盤面・設定・試合時計を変更しない。角度・起伏は再読み込みで初期値に戻る。
- WebGLの初期化に失敗した場合、平面版に戻して理由を表示する。WebGLコンテキスト消失時も平面版へ戻し、立体版の復帰にはページの再読み込みを案内する。


## 反転音

PC側のWeb Audio APIで短い帯域制限ノイズと減衰する正弦波を合成する。外部音源・マイク・サーバーからの音声配信は使わない。PCで「音をON」または「試聴」を押すとAudioContextを開始・再開する。音量の初期値は35%。ON状態はページ再読み込みを越えて保存せず、音量だけ保存する。

`src/client/flip-events.ts` が描画用磁化の正負の変化を検出し、`src/client/magnet-sound.ts` が発音する。正側は8bit値138以上、負側は117以下まで移ったことを確認し、ゼロ近傍の揺らぎによる連打を防ぐ。操作可能な段階で、到達した色のプレイヤーが磁場を出しており、その作用範囲内にある反転だけを対象にする。これは局所的な操作のフィードバックであり、外場による変化と自然緩和を厳密に因果分解する計算ではない。

反転数を短時間でまとめ、発音はプレイヤーごとに最大約12回/秒。量に応じて音量と減衰時間を変え、位置に応じて左右に振り分ける。発音後は音声ノードを切断して解放する。消音・状態遷移・切断・画面非表示では残っている発音と待ち行列を止める。待機、リセット、最後の自然緩和や作用範囲外の反転は鳴らさない。


## 拠点争奪モード（control）

ユーザーと確認したルール：90秒の保持時間による勝負、円内60%以上を連続1秒維持して占領、60%未満で中立化、中央と両者の橋の先の固定3拠点。

`Mode` に `control` を追加。`Game.setup` はこのモードでは盤面を `bridges` に固定する。面積対戦 `battle` と練習 `practice` は従来のまま残す。二人分の接続・準備完了を要求し、3秒カウントダウン後、90秒間だけ操作・占領判定・加点を進める。75秒での緩和への移行は行わない。

拠点は半径6格子で、A=(127.5,27.5)、B=(95.5,53.5)、C=(63.5,79.5)。AとCは180度回転で入れ替わり、Bは中心で不変となる。初期の磁化は従来と同じ。

`src/server/control.ts` が毎ゲーム更新の数値計算後に円内のFloat64磁化の正負を集計する。ゼロの格子は両者に0.5ずつ配分する。60%以上の側が連続60更新を満たすと占領し、次の更新から占領者へ1/60点ずつ加点する。途中で60%を割る、または占領候補が変わると、その占領待ちカウントをリセットする。保持者が60%を割った更新では加点しない。複数拠点は独立に加点する。

得点は内部では整数の保持更新数で累積し、表示時に60で割る。勝敗はこの整数値で比較して、表示丸めに依存しない。同点は引き分け。保持数・面積による決着の補正は行わない。途中で領土がゼロになっても終了しない。通信断・一時停止・再開カウントダウン中は得点も占領経過も凍結する。待機画面への復帰・再戦で得点、占領、途中カウントをリセットする。

Snapshotに `control: ControlView | null` を追加し、拠点座標、保持者、占領候補、占領進捗、円内の色割合、両者の得点と保持拠点数（通常時の毎秒得点）を配信する。他モードではnull。スマホから拠点や得点を直接操作するメッセージは受け付けない。

PCでは得点を主表示、面積を補助表示とし、A/B/Cの占領カード、2Dの円と旗、3Dの地形に沿う円と旗を追加する。スマホは得点と各拠点の所有者を表示する。表示切替は判定や得点へ影響しない。
